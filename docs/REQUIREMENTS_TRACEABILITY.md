# Workbench requirements traceability

The public enhancement-workbench format 7 carries append-only `H01`-`H76`, `N01`-`N82`,
`R001`-`R102`, and `E001`-`E095` registers with distinct product, evidence, and approval states.
They bind every real-repository audit recommendation to a product resolution, acceptance criterion,
authority, live resolution state, and machine projection. Its exact analysis digest, artifact
freshness, precision risks, and acceptance targets keep implemented capability separate from
missing project evidence and human approval.

2026-08-08 refinement: the self-contained HTML coverage workspace embeds the non-certifying
diagnostic scorecard, ordered remediation actions, and human-disposition calibration. Cross-stack
evidence composes bounded imported-router tables/loops with named client base constants and
conventional request wrappers while excluding web-test literals from deployed-client metrics.

The `pysfmea-enhancement-workbench-7` Python/CLI/JSON/HTML projection adds explicit operational
traceability across all 56 foundational enhancement items, 76 real-repository hardening items,
82 post-hardening items, and 102 real-run resolution items
while keeping product capability, project evidence, and human-authority closure separate.

Last implementation audit: 2026-08-27 · PySFMEA 0.61.0 · analysis schema 0.6

Governed-analysis persistence traceability includes 200 MB identity-stable ingestion and hashing,
strict duplicate-free finite UTF-8 JSON, shared 100-level/5,000,000-node limits, bounded output
serialization, final-path-safe atomic replacement, destination-race refusal, and prior preservation.

Package-authentication traceability includes inspected/opened/final identity-revalidated key,
envelope, and manifest ingestion; strict duplicate-free finite UTF-8 envelope/manifest decoding
with contract-scaled byte/depth/node limits; fresh package verification that cannot be bypassed by
a supplied verdict; verified-snapshot digest reconciliation; and atomic race-refusing signature
publication.

Standalone-report traceability includes one shared 256 MiB encoded-artifact boundary for CSV,
Markdown, JSON, SARIF, CycloneDX, SFTA, visual, assurance-register/work-queue, individual-schema,
publication-catalog, diagram-bundle, and HTML outputs; exact BOM/newline compatibility; final-link
and non-file refusal; synchronized sibling staging; concurrent-change reconciliation; atomic
replacement; prior-file preservation; and staging cleanup. Catalog refresh retains its exact
pre-validation absent/file state and refuses any later owner or content change.

Public-contract ingestion traceability includes one strict governed-JSON boundary for offline
schema files and the publication catalog: bounded binary consumption, regular non-link inputs,
inspected/opened/final identity reconciliation, strict UTF-8, duplicate-key and non-finite-number
rejection, iterative depth/node ceilings, and structured verifier failures before canonical hashing.

Cross-output integration traceability includes a closed declaration registry plus one digest-bound
entity for every top-level analysis section. Standalone verification reconciles section identity,
projection mode/status, declared entity kinds, declared relationship channels, sampled identities,
complete identity-set digests, and summary accounting. Unknown populated outputs and registered
semantic outputs without material links remain distinct review leads. A bounded second layer creates
one digest-bound entity/profile per projectable nested record, independently recomputes its
identity-correlated entity/relationship target sets and graph witnesses, and counts unresolved or
bound-omitted records as high-priority gaps. Exact verification binds section and record locators,
digests, and tokens back to the governed analysis. Adversarial tests rewrite witness metadata,
introduce a source record with no valid component, and exhaust the record bound; each case remains
fail-visible without promoting identity correlation to proof of correctness.

## Authority boundary

Generated-test format 3 retains format 2's reconciliation of each fault-detection claim to two distinct analysis-linked
execution records, the same exact generated-test digest, passing baseline and failing seeded
statuses, content-sealed manifests, a confined evidence root, and every retained raw artifact's
recorded size and SHA-256. It additionally gates frozen-before-outcome selection, repository,
framework, domain, per-stratum and category populations, decision balance, and concentration. The
campaign result derives 25 gates and replays this chain against the exact corpus; digest-only or
unavailable evidence receives no credit, and declared strata do not prove representativeness.

No test above authorizes a risk decision. A passing tool suite establishes regression
evidence for the implemented software only. Project teams must independently establish
system context, hazard consequences, applicability, control adequacy, test oracles,
evidence sufficiency, residual risk, waiver/acceptance authority, and any required tool
qualification or certification credit.
