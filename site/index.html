A disciplined workflow

Discovery is the beginning, not the verdict.

Every machine-generated lead stays separate from human acceptance and verification evidence.

  1. 1

    Define the system

    Capture boundaries, hazards, operating modes, safe states, interfaces, timing, and assumptions.

  2. 2

    Scan the repository

    Extract a bounded static model of code, calls, data flow, exception paths, and resilience semantics.

  3. 3

    Review failure modes

    Inspect local, next-higher, and end effects with exact source locations and guidance relationships.

  4. 4

    Close with evidence

    Turn accepted findings into testable obligations, register implementations, and retain results.

Analysis depth

One repository, multiple assurance views.

Structure

Architecture & interfaces

Components, entry points, routes, external dependencies, contracts, deployment topology, and shared-fate regions.

Behavior

Sequences & propagation

Bounded call sequences, typed exception flow, state transitions, data/alias flow, and failure cascade paths.

Resilience

Timing & controls

Retries, deadlines, circuit breakers, transactions, idempotency, resource bounds, and concurrency review leads.

Traceability

Guidance & citations

Versioned NASA/FAA source locators and typed rule-to-finding relationships with integrity and applicability metadata.

Hardening

Executable assurance

Finding-derived verification obligations, fault-injection plans, test scaffolds, execution records, and evidence review.

Communication

Reports & diagrams

Self-contained HTML, canonical diagram JSON, fault trees, worksheets, SARIF, SBOM, and portable review packages.

Evidence discipline

Claims keep their authority boundaries.

Static evidence, runtime observations, guidance mappings, machine suggestions, human decisions, test executions, and independent reviews remain distinct. Cross-references add leverage without turning correlation into proof.

Local-first by design

Start with one repository.

Install in an isolated environment, initialize governance, scan, and open the self-contained report locally.

TerminalPython 3.11+
python -m pip install "git+https://github.com/willtran87/project-py-sfmea.git"
sfmea init /path/to/repository
sfmea scan /path/to/repository
sfmea report /path/to/repository/sfmea-analysis.json
sfmea review /path/to/repository/sfmea-analysis.json

Important boundary

A scanner can accelerate assurance. It cannot approve risk.

PySFMEA provides review leads and evidence infrastructure. System effects, severity, occurrence, control adequacy, compliance, and residual-risk acceptance remain engineering decisions.
